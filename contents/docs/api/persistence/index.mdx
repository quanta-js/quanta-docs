# Persistence API

<Note title="These examples use `createStore`">
`createStore` builds a store instance immediately and is still fully supported.
In application code prefer [`defineStore`](/docs/api/define-store), which
returns an accessor you call — it is safe at module scope on a server and needs
no container passed around. Everything on this page applies to both.
</Note>


QuantaJS persistence automatically saves and rehydrates store state with adapter-based storage.

## Exports

```ts
import {
  createPersistenceManager,
  LocalStorageAdapter,
  SessionStorageAdapter,
  IndexedDBAdapter,
  MigrationManager,
  createMigrationManager,
  CommonMigrations,
} from '@quantajs/core';
```

## `PersistenceConfig<T>`

```ts
interface PersistenceConfig<T = any> {
  adapter: PersistenceAdapter;
  serialize?: (data: any) => string;
  deserialize?: (data: string) => any;
  migrations?: Record<number, (data: any) => any>;
  version?: number;
  debounceMs?: number;
  include?: Array<keyof T>;
  exclude?: Array<keyof T>;
  transform?: {
    in?: (data: any) => any;
    out?: (data: any) => any;
  };
  onError?: (
    error: Error,
    operation: 'read' | 'write' | 'remove' | 'watch-setup'
  ) => void;
  validator?: (data: any) => boolean;
}
```

## Adapter Classes

### `LocalStorageAdapter`

```ts
const adapter = new LocalStorageAdapter('app-store');
```

- Uses browser `localStorage`
- Supports cross-tab sync through `storage` events

### `SessionStorageAdapter`

```ts
const adapter = new SessionStorageAdapter('session-store');
```

- Uses browser `sessionStorage`
- Session-scoped persistence

### `IndexedDBAdapter`

```ts
const adapter = new IndexedDBAdapter('store-key', 'app-db', 'stores', 1);
```

- Async persistence for larger datasets
- Better fit for high-volume/local-first workloads

## Store-Level Usage

```ts
import { createStore, LocalStorageAdapter } from '@quantajs/core';

const userStore = createStore('user', {
  state: () => ({
    profile: null as null | { id: string; name: string },
    theme: 'light' as 'light' | 'dark',
  }),
  persist: {
    adapter: new LocalStorageAdapter('user-store-v1'),
    version: 1,
    include: ['profile', 'theme'],
    debounceMs: 250,
  },
});
```

## Validation and Transform

```ts
persist: {
  adapter: new LocalStorageAdapter('settings-v2'),
  transform: {
    out: (data) => ({ ...data, savedAt: Date.now() }),
    in: (data) => ({ ...data, savedAt: undefined }),
  },
  validator: (data) => typeof data === 'object' && data !== null,
  onError(error, operation) {
    console.warn('Persistence error:', operation, error.message);
  },
}
```

## Migrations

```ts
import { CommonMigrations } from '@quantajs/core';

persist: {
  adapter: new LocalStorageAdapter('app-store'),
  version: 3,
  migrations: {
    2: CommonMigrations.addProperty('featureFlags', {}),
    3: CommonMigrations.renameProperty('user', 'currentUser'),
  },
}
```

## `PersistenceManager`

When persistence is enabled, stores expose `store.$persist`:

```ts
interface PersistenceManager {
  save(): Promise<void>;
  load(): Promise<void>;
  clear(): Promise<void>;
  getAdapter(): PersistenceAdapter;
  isRehydrated(): boolean;
  destroy(): void;
}
```

## `store.$hydrated`

```ts
await store.$hydrated;
```

A promise that resolves once restoration has finished. Prefer it over polling
`$persist.isRehydrated()` — it works whether or not persistence is configured
(resolving immediately when it is not), so calling code does not have to
branch.

```ts
// Before rendering anything that depends on restored state:
await useSettingsStore().$hydrated;
```

`isRehydrated()` still exists for a synchronous check.

## Behavior Notes

- Rehydration is attempted automatically during store setup.
- Invalid/malformed payloads are safely rejected and routed to `onError`.
  Dangerous keys (`__proto__`, `constructor`, `prototype`) are rejected on every
  ingest path — load, cross-tab sync, migrations and transforms.
- Cross-tab sync checks `storageArea`, contains parse failures, and refuses
  payloads claiming a newer schema version than the running code.
- `clear()` re-arms auto-save rather than disabling it for the rest of the
  session, and `save()` always writes — both were fixed in 2.1.
- Adapters are SSR-safe: on the server they degrade to a no-op instead of
  throwing from their constructor.
- Call `destroy()` to clean up persistence watchers/listeners for disposed
  stores — or dispose the [container](/docs/api/containers), which does it for
  every store at once.
